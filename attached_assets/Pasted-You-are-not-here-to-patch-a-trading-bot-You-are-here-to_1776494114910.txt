ULTIMATE DESIGN PHILOSOPHY
==================================================

The best trading model is not the most complex.
The best trading model is the one that is:
- most truthful
- most calibrated
- best at ranking real edge
- best at rejecting bad trades
- best at understanding its own uncertainty
- best at adapting when the market changes
- best at stopping when it no longer understands the market

We are not trying to build:
- a dual-specialist system
- a heuristic score formula machine
- a threshold-and-gate forest
- a fake-confidence engine
- a beautiful backtest that dies in live conditions

We are trying to build:
- a market-state intelligence engine
- a direct expectancy engine
- an abstention engine
- a self-auditing engine
- a self-preservation engine

==================================================
THE 5-LAYER MARKET INTELLIGENCE ORGANISM
==================================================

Build the system as 5 layers.

----------------------------------
LAYER 1 — SIGNAL-TRUTH LAYER
----------------------------------
Purpose:
Continuously measure whether the data currently contains real predictive signal.

This layer must:
- compute IC by feature, symbol, regime, horizon
- compute mutual information / nonlinear dependence
- detect feature drift
- detect target drift
- detect regime drift
- detect out-of-distribution states
- produce a model-trust score
- determine whether the downstream model should trust its own output

This layer is non-negotiable.
No model should trade unless this layer says the environment is still learnable enough.

----------------------------------
LAYER 2 — FAST SHIFT LAYER
----------------------------------
Purpose:
Detect instant market changes and shock conditions.

This layer should attempt to detect:
- abrupt trend breaks
- liquidation cascades
- volatility explosions
- reversal bursts
- continuation bursts
- flow imbalance shocks
- instability / disorder events
- market stress conditions

If true event data is available, use:
- news/sentiment embeddings
- liquidation data
- OI shocks
- funding shocks
- basis / premium dislocations
- spread/depth stress
- aggressor flow

If not available, explicitly say what is missing and build the best proxy version from existing data.

This layer does not directly decide trades.
It produces a shock/instability embedding and fast-state context.

----------------------------------
LAYER 3 — SLOW REGIME LAYER
----------------------------------
Purpose:
Understand the broad market environment.

This layer should infer:
- trend regime
- chop regime
- high-vol vs low-vol regime
- BTC-correlated vs idiosyncratic regime
- liquidity regime
- macro risk-on / risk-off regime
- directional persistence vs mean-reversion tendency

This layer also does not directly decide trades.
It produces a regime embedding and regime confidence.

----------------------------------
LAYER 4 — EXPECTANCY DECISION LAYER
----------------------------------
Purpose:
Make the actual trade decision.

This must be:
- one unified model
- one trunk only
- no dual specialists
- no long-vs-short trunk split
- no fake specialization

Inputs:
- top validated features only
- symbol embedding if useful
- regime embedding from Layer 3
- shock embedding from Layer 2
- trust score from Layer 1

Outputs:
1. LONG / HOLD / SHORT logits
2. direct predicted net expectancy for LONG
3. direct predicted net expectancy for SHORT
4. path-quality score (clean vs noisy move)
5. optional MAE/MFE estimates if helpful
6. optional uncertainty only if it becomes truly calibrated

Important:
The system must rank by direct predicted expectancy.
Do NOT build another handcrafted score formula.

----------------------------------
LAYER 5 — SELF-AUDIT / SELF-PRESERVATION LAYER
----------------------------------
Purpose:
Detect when the model is failing, drifting, or becoming dangerous.

This layer must:
- detect when confidence calibration breaks
- detect when ranking becomes non-monotonic
- detect when the model collapses to one class
- detect when signal has disappeared
- detect when the current market is out-of-distribution
- lower trust automatically
- stop trading automatically if needed
- trigger retraining / fallback mode recommendations

This is what makes the system exceptional.
It does not merely predict.
It audits its own intelligence.

==================================================
STAGE 7 — INFERENCE POLICY
==================================================

Inference must be principled.

For each bar:
1. Layer 1 measures trust / signal validity
2. Layer 2 estimates shock state
3. Layer 3 estimates regime state
4. Layer 4 predicts LONG / HOLD / SHORT and direct expectancy
5. Layer 5 audits whether the output should be trusted

Trade only if:
- trust layer says signal is valid enough
- chosen side has clearly positive expectancy after costs
- action head agrees
- path quality is acceptable
- current regime supports the trade
- current shock state does not invalidate it
- the trade lies in a historically profitable expectancy band

Otherwise HOLD.

Do not use giant gate trees.
Keep prediction, policy, and risk separate.
