B) Extend MultiHeadDataset to return the missing targets

In training/multihead_trainer.py, change MultiHeadDataset to return:

seq features

class_label

forward_return

trading_targets tensor (3 values)

candle_targets tensor (n_future_candles, 3)

Patch shape logic (recommended)

Your candle targets are in a flat vector (because columns are like candle_delta_close_1, ...high_1, ...low_1, …).
Convert it to [n_future, 3].

Example edit:

class MultiHeadDataset(Dataset):
    def __init__(..., entry_offset, sl_distance, tp_distance, candle_targets, n_future_candles=5, sequence_length=100):
        ...
        self.entry_offset = entry_offset.astype(np.float32)
        self.sl_distance  = sl_distance.astype(np.float32)
        self.tp_distance  = tp_distance.astype(np.float32)

        self.candle_targets = candle_targets.astype(np.float32)  # [N, n_future*3]
        self.n_future = n_future_candles
        ...

    def __getitem__(self, idx):
        ...
        trading = np.array([self.entry_offset[actual_idx], self.sl_distance[actual_idx], self.tp_distance[actual_idx]], dtype=np.float32)

        c = self.candle_targets[actual_idx]
        c = c.reshape(self.n_future, 3)  # [n_future, 3]

        return (
            torch.from_numpy(seq),
            torch.tensor(self.class_labels[actual_idx]),
            torch.tensor(self.forward_returns[actual_idx]),
            torch.from_numpy(trading),
            torch.from_numpy(c),
        )

4) Fix inference so it actually uses multi-head models (must do)

Right now:

/predict/candles → model_manager.predict() (classification-only output)

Multihead outputs are only used in /predict/quantile

The clean solution

Add a new endpoint:

/predict/multihead/candles

This endpoint should:

compute features exactly like /predict/candles

call model_manager.predict_multihead(features_seq)

return direction + mu/sigma/quantiles + entry/sl/tp + future candles

Why a new endpoint?

Because your current /predict response schema is classification-focused. Multihead response needs extra fields.

5) One more alignment issue: “which scaler belongs to which model”

Your server loads the most recently modified scaler from saved_models/:

all_scaler_files.sort(key=mtime, reverse=True)
self.scaler = joblib.load(all_scaler_files[0])


If you trained multiple models, you can easily load:

Model A checkpoint

Scaler from Model B

That silently breaks inference.

Fix

When saving a model, save:

checkpoint .pt

scaler .joblib

feature columns .txt
…with the same prefix, and store that prefix in a small metadata json.

Example:

best_transformer_multihead.pt

best_transformer_multihead_scalers.joblib

best_transformer_multihead_feature_columns.txt

best_transformer_multihead_meta.json

Then in server, when you load a model file, load the scaler with the same prefix.

This one change removes a huge “random mismatch” class of bugs.
