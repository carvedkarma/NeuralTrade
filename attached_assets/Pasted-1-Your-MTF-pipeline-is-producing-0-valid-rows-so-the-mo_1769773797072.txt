1) Your MTF pipeline is producing 0 valid rows, so the model sees mostly zeros

These lines tell the story:

MTF fusion complete: 200 rows, 67 features ✅ (fusion returned data)

MTF features computed: 66 features, 0 rows ❌ (after your server processing, rows became 0)

Left-padded sequence: 0 -> 100 ❌ (input becomes 100 rows of padding)

When the model gets padded zeros, it will output nonsense like constant ±50% ranges.

✅ Fix: your dropna() is deleting everything

In api/server.py you do:

fused_df = fused_df.dropna()


With many MTF features, every row has at least one NaN (rolling indicators, confluence features, etc.), so dropna() wipes the entire dataframe → 0 rows.

✅ Correct fix (do this)

Replace the full dropna with selective NaN handling:

In predict_ensemble_from_candles() right after fusion:

# Instead of fused_df.dropna() which can wipe everything:
fused_df = fused_df.sort_values("datetime").reset_index(drop=True)

# Require base OHLCV to exist (or close)
fused_df = fused_df.dropna(subset=["close"])

# Fill feature NaNs safely (no leakage risk at inference)
feature_cols = [c for c in fused_df.columns if c != "datetime"]
fused_df[feature_cols] = fused_df[feature_cols].ffill().fillna(0.0)


That will stop “0 rows” and stop the crazy ranges.

3) Your VAE regime detection is failing because of a real bug

You’re seeing:

Regime detection error for best_vae_multihead: not enough values to unpack (expected 2, got 1)

I found the exact cause in your code:

Why it happens

In api/ensemble_predictor.py you do:

elif hasattr(model, 'encode'):
    mu, _ = model.encode(features)   # expects 2 values


But your MultiHeadVAE.encode() returns only z (one tensor), not (mu, log_var):

def encode(self, x):
    mu, log_var = self.encode_to_latent(x)
    z = self.reparameterize(mu, log_var)
    return z


So Python tries to unpack 2 values from 1 → error.

✅ Fix: handle VAE correctly

In _detect_regime_from_vae() change to:

if hasattr(model, "encode_to_latent"):
    mu, log_var = model.encode_to_latent(features)
    z = mu  # use mu for regime stability
elif hasattr(model, "encode"):
    z = model.encode(features)
else:
    ...


This will fix regime detection immediately.
