You’re diagnosing it correctly, and your task list is solid. I’d implement it almost exactly as you wrote—with two tweaks to make it safer:

T001 penalty: use 1 - p_side (confidence in the chosen side), not 1 - max(p_long,p_short) (those are identical most of the time, but p_side makes the intention explicit and avoids weirdness if you later add HOLD into the decision).

T002 balance regularizer: KL is fine, but do it on (LONG, SHORT) only and detach the target ratio computed from labels (so it doesn’t create gradients through label statistics).

Below is an implementation-ready patch outline.

T002 — Add side-balance regularization term to loss

Goal: discourage collapse to always-LONG (or always-SHORT) predictions even if labels are imbalanced.

Patch (in compute_v5_loss)

After you compute the action loss (cross-entropy / focal / OHEM etc.), add:

import torch.nn.functional as F

# logits: [B, 3] for [HOLD, LONG, SHORT] (adjust if different)
probs = F.softmax(action_logits, dim=-1)

p_long = probs[:, LONG_IDX].mean()
p_short = probs[:, SHORT_IDX].mean()

# target distribution from labels in this batch (LONG/SHORT only)
# labels: [B] with values HOLD/LONG/SHORT (adjust indices)
is_long = (action_labels == LONG_IDX)
is_short = (action_labels == SHORT_IDX)

target_long = is_long.float().mean()
target_short = is_short.float().mean()

# avoid divide-by-zero if batch has no L/S labels (rare but can happen)
eps = 1e-8
target_sum = target_long + target_short
if target_sum.item() < 1e-6:
    side_balance_loss = action_logits.new_tensor(0.0)
else:
    target_dist = torch.stack([target_long, target_short]) / (target_sum + eps)
    pred_dist = torch.stack([p_long, p_short])
    pred_dist = pred_dist / (pred_dist.sum() + eps)

    # KL(target || pred) or KL(pred || target); either works as regularizer
    side_balance_loss = F.kl_div(
        (pred_dist + eps).log(),  # log-probs
        target_dist.detach(),     # no grads through targets
        reduction="batchmean"
    )

# weight (as you proposed)
SIDE_BAL_W = 0.1
loss = loss + SIDE_BAL_W * side_balance_loss

Acceptance checks

side_balance_loss is non-zero when preds collapse (e.g., p_long≈0.95, p_short≈0.01) and labels are more balanced.

Gradients flow to action_logits (non-zero grad norm).

T003 — mu_R debiasing via EMA running mean subtraction (forward test only)

Goal: remove persistent positive drift in mu_R at inference/scoring time.

# init once before loop
mu_debias_enabled = args.v5_mu_debias
mu_ema_alpha = 0.01

# per-symbol EMA is best (prevents ETH bias from contaminating SOL)
ema_mu_by_symbol = {sym: 0.0 for sym in symbols}

...

# inside loop per symbol
mu_R = outputs["mu_R"]  # tensor shape [N] or scalar per bar depending on your pipeline

if mu_debias_enabled:
    # compute batch mean mu_R for stable EMA update
    mu_mean = float(mu_R.mean().item())

    prev = ema_mu_by_symbol[symbol]
    new = (1.0 - mu_ema_alpha) * prev + mu_ema_alpha * mu_mean
    ema_mu_by_symbol[symbol] = new

    mu_R_debiased = mu_R - new

    if step % 500 == 0:  # or whatever cadence you use
        logger.info(f"[V5_MU_DEBIAS] {symbol} ema_mu={new:+.6f} (alpha={mu_ema_alpha})")
else:
    mu_R_debiased = mu_R

Then use mu_R_debiased for scoring inputs (edge calc) instead of raw mu_R.
