REPLIT AGENT — BUG FIX: “Trades recorded when paper not enabled”

Problem:
Dashboard shows trades being taken even when paper trading is NOT enabled.

Root cause:
Trade creation / position tracking is happening even when execution_mode != PAPER.
Execution toggle currently only blocks exchange orders, not trade journaling.

GOAL:
Make execution modes strict and mutually exclusive:

Modes:
- SIGNAL_ONLY: no positions opened, no trades recorded, only cycle logs + “would enter” messages
- PAPER: positions opened + recorded + simulated exits (TP/SL/TradeManager)
- LIVE: real orders placed + recorded + exits tracked from exchange (or simulated only if explicitly allowed)

TASKS:

1) Add one single authoritative flag:
execution_mode in {"signal_only","paper","live"}
- default MUST be "signal_only" unless user explicitly sets --paper or --live

2) Gate trade creation:
In live_runner.py (where a trade is opened / Position is created / POST /trades is called):
IF execution_mode == "signal_only":
  - DO NOT create Position
  - DO NOT POST /trades (no trade rows)
  - DO push a cycle log with decision="SIGNAL_ONLY" and include:
    would_enter=true, side, entry, sl, tp, lane, p_enter, reasons

3) Gate TradeManager:
TradeManager must only run when execution_mode in {"paper","live"}.
Never run TM in signal_only.

4) Add mandatory startup log:
[MODE] execution_mode=<signal_only|paper|live> paper_enabled=<bool> live_enabled=<bool>

5) Add mandatory per-trade guard log:
When trade would be taken:
- If signal_only: [NO_EXEC] would_open_trade symbol=... lane=... p=...
- If paper: [PAPER_OPEN] ...
- If live: [LIVE_OPEN] placing_order ...

6) UI labeling:
If a row is not a real trade (signal_only), it must never appear in Trade Journal.
Only “paper/live trades” show in journal.

Acceptance test:
Run without --paper and without --live:
- Trades table must remain empty
- Only cycle logs show “SIGNAL_ONLY”
Then run with --paper:
- Trades appear normally
