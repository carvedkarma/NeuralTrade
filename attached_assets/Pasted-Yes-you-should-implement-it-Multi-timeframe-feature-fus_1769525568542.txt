Yes — you should implement it. Multi-timeframe feature fusion is one of the highest-ROI upgrades you can do while still staying “candles only”.

The key is to implement it in a leakage-proof way and keep it simple + stable at first.

How to implement it safely
1) Pick a base timeframe (recommend: 15m)

All predictions happen on the close of each 15m candle.

2) Build features per timeframe separately

For each TF (5m, 15m, 1h, 4h):

compute OHLCV-derived features independently (returns, ATR, RSI, wick/body ratios, z-scores, trend strength, rolling vol, etc.)

keep each TF’s feature columns suffixed: _5m, _15m, _1h, _4h

3) Align to the 15m timeline using “last completed candle”

This is the crucial leakage guard.

For a 15m timestamp t:

5m features must use only candles with close ≤ t

1h / 4h features must use the most recent completed 1h/4h candle with close ≤ t

Implementation rule: merge_asof(direction="backward") on candle close timestamps.

4) Add confluence features (your “aligned?” idea)

This is where real edge often comes from. Examples:

trend sign agreement: sign(ret_1h) == sign(ret_15m)

RSI regime: RSI_4h > 50 and RSI_1h > 50

volatility regime: vol_1h / vol_4h, atr_15m / atr_1h

momentum alignment: ema_slope_5m, ema_slope_15m, ema_slope_1h

Keep these as extra columns, not a separate model stage.

Start with the best minimal set

Don’t explode feature count. Start with:

5m (micro momentum)

last N returns (1, 3, 6 bars)

range%, wick/body ratios

rolling vol (20)

15m (decision TF)

same as above + RSI/ATR

1h (trend context)

EMA slope, MACD-ish (difference of EMAs), RSI

rolling vol (50)

4h (regime)

trend strength / slope

vol regime

distance from long EMA (mean reversion vs trend)

That’s enough to get a big improvement.

Model integration options
Option A (recommended first): single model, concatenated features

Just feed the fused feature vector into your existing Transformer/LSTM/CNN.

This is simplest and works well.

Option B (later): separate encoders per timeframe + fusion layer

Better but more work. Do this only after Option A proves value.

One thing to watch out for

Lower timeframe (1m/5m) can add noise. The trick is:

use it mainly for momentum + volatility

keep window lengths short

don’t overfit with too many indicators
