A few things I’d tighten next so you don’t accidentally build a model that looks good on PR-AUC but still loses money.

1) Two critical checks on your labels
A) Avoid “TP-only positive” bias

Right now ENTER=1 only when TP hits first. That’s clean, but it can bias the model to only take ultra-clean moves and ignore “good but messy” trades.

Add a second positive definition (optional, but often better):

ENTER=1 if realized R at expiry is ≥ +R_min (e.g., +0.5R), even if TP wasn’t hit.

This gives you more positives and reduces brittleness.

B) Ensure labels use the same SL/TP/expiry as evaluation

Make sure the exact same:

k_sl, k_tp, horizon_bars

candle fields (high/low)

cooldown rules (if any)

are used in both labeling and walk-forward evaluation. Any mismatch will reintroduce the instability you just escaped.

2) Your inference gates are good — but make them learnable/robust

You’ve got:

p_enter >= 0.55

HTF alignment

slope min

range position filter

That’s fine, but do this one tweak:

Replace fixed p_enter threshold with “top percentile”

Because distributions drift across regimes.

Example:

take top X% of p_enter per day (or per 1,000 bars)

enforce min spacing/cooldown

This keeps your trade frequency stable and avoids threshold fragility.

3) Add the one metric that matters: realized R distribution

Alongside PR-AUC, log:

avg win R, avg loss R

median R

%TP, %SL, %expiry

PF / expectancy on OOS slice

PR-AUC can improve while expectancy stays negative if you’re selecting “good setups” that still don’t survive costs.

4) Watch for a common failure mode: label leakage via HTF alignment

You already shift HTF by 1 bar, good. Still verify:

the “trend aligned” state at time t uses only HTF bars closed before t.

the gate doesn’t accidentally use future-slope info due to rolling windows.

A simple debug print of timestamps for random samples catches this.

5) Next optional upgrade (high ROI): MAE/MFE heads

Once ENTER is working, the best next addition is:

predict MAE_hat and MFE_hat

trade only if MFE_hat/MAE_hat > R_min

This usually improves expectancy more than any threshold tuning.
