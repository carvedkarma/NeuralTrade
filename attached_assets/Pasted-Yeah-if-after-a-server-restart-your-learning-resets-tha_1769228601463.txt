Yeah — if after a server restart your “learning” resets, that almost always means you’re storing state in RAM or local ephemeral files, not in a persistent database + model checkpoints.

Here’s exactly how to fix it so nothing is lost on restart (data, patterns, model weights, stats, paper trades).

1) Identify what is getting wiped

A restart should not erase any of these:

Must persist

candles (1m + 15m)

features

pattern clusters + embeddings

model weights (ML + DL)

calibration params

backtest results

paper trade portfolio, positions, trades

Usually gets lost (common causes)

in-memory arrays/maps

“learning progress” stored in a JS variable

SQLite database created in /tmp or project build folder

model saved to a relative path that changes on deploy

Replit/container filesystem not mounted as persistent volume

2) The golden rule

Everything important must live in one of these:

Database (Postgres preferred, SQLite okay if stored in persistent path)

Versioned model artifact files (saved to persistent storage)

A small config table to track “latest model version”, “last trained ts”, etc.

Nothing important should live only in RAM.

3) The most common reason on Replit

On Replit, you often lose data if:

you store DB under a path that gets reset (build directory)

you don’t mount a persistent volume

you use in-memory DB mode (sqlite::memory:)

you recreate tables on startup

Quick check

Ask your agent:

“Where is the DB file located?”

“Do we run migrations or do we DROP/CREATE on startup?”

“Do we ever call resetLearning() on boot?”

4) Fix checklist (tell your agent to implement all)
A) Database persistence (required)

Best: Postgres (persistent, safest)

Use DATABASE_URL

Use migrations (Prisma/Drizzle/Knex/Alembic)

If using SQLite: store it in a persistent folder, e.g.

/home/runner/<project>/data/app.db (or ./data/app.db)

Ensure ./data is not wiped

Do NOT use:

:memory:

/tmp

./dist

./build

B) Never recreate tables on restart

On server boot you should only:

run migrations

verify tables exist

You must not:

drop tables

truncate tables

“seed” sample data unless user explicitly asked

C) Persist “learning state”

Create a table like learning_state with:

last_train_ts

last_feature_ts

model_version

patterns_version

training_progress

is_frozen

So UI reads progress from DB, not memory.

D) Save model artifacts as versioned files

Every time training finishes:

save model to: ./artifacts/models/<model_version>/...

write model_version to DB

Examples:

LightGBM/XGBoost: .txt / .json / .bin

PyTorch: .pt

Calibration: .json

On boot:

read learning_state.model_version

load those artifacts into memory

If artifact missing → show “model not ready”.

E) Persist pattern memory properly

Patterns shouldn’t be recomputed from scratch on every boot.

Store:

pattern_clusters (cluster id, regime, centroid embedding, sample count)

pattern_members (ts → cluster id)

pattern_stats (win%, MAE/MFE median, time_to_MFE, etc.)

embedding_vectors (ts → embedding blob)

On boot:

load current cluster centroids/stats

only compute new embeddings for new candles

F) Make ingestion + training resumable

Use “watermarks”:

last_ingested_ts_1m

last_resampled_ts_15m

last_features_ts

At startup:

resume from the last watermark

backfill any missing gaps

5) One message to send your Replit Agent (copy/paste)

Paste this:

On restart we are losing learning/data. Fix persistence end-to-end:

Move all critical state out of RAM into DB + artifacts.

Use Postgres preferred; if SQLite, store at ./data/app.db (NOT memory, NOT /tmp, NOT dist/build). Ensure ./data persists.

Remove any startup code that recreates/drops/truncates tables. Use migrations only.

Add learning_state table to persist: last_train_ts, last_feature_ts, model_version, patterns_version, training_progress, freeze flags. UI must read from DB.

Save trained models as versioned artifacts: ./artifacts/models/<version>/model.* + calibrator.json. Save version in DB. On boot, load latest version from DB.

Persist pattern memory: clusters, members, stats, embeddings in DB. Do not recompute everything on boot; only update incrementally from last watermark.

Add ingestion/training watermarks so collectors resume after reboot without duplication or gaps.

Add a “Startup Integrity Check” endpoint that reports: DB path, candle counts, last timestamps, model version loaded, patterns version loaded.

6) Quick way to confirm it’s fixed

After implementing:

Ingest some candles, train once, create patterns.

Restart server.

Verify these values stay the same:

candle counts

pattern count

model version

last_train_ts

paper trade history

If any reset → that component isn’t persisted.
