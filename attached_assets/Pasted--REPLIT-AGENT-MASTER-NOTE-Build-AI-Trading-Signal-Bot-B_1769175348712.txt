✅ REPLIT AGENT MASTER NOTE — Build “AI Trading Signal Bot” (BTCUSDT Futures 15m, Signal-Only)
Mission

Build a single-user web app that generates institutional-grade trading signals for BTCUSDT USDT-M Perpetual Futures on 15m timeframe.
The bot must perform deep analysis using:

Historical pattern similarity (“old pattern memory”)

Indicators (including Kalman Trend Levels)

Futures microstructure (OI, funding, liquidations, mark/index)

ML baseline + Deep Learning model

Strict regime gating + risk plan

🚫 The bot must NOT place trades.
✅ It must output LONG / SHORT / HOLD with a full Shot Plan (entry/stop/TP/hold time + reasons).

1) Core Output (what the app must say every 15m)

For every 15m candle close, generate:

Signal: LONG / SHORT / HOLD

Confidence: 0–100% (calibrated probability)

Regime: Trend Up / Trend Down / Chop / Shock

Strategy selected: (Kalman Trend / Mean Reversion / Shock)

Entry Zone: [low, high]

Stop Loss (price)

Take Profit(s) (TP1, TP2, optional trail)

Risk/Reward

Expected Hold Time (e.g., “2–6 candles”)

Estimated Costs (fees + slippage + funding risk)

Edge = expected_move − costs

Reasons: top 5 reasons + veto reasons (why HOLD if HOLD)

Signal must be conservative: HOLD is expected most of the time.

5) Kalman Trend Levels Strategy (must implement)

Implement a 1D Kalman filter (two lines):

fast kalman (Short_len default 70)

slow kalman (Long_len default 250)

Trend:

Up if fast > slow

Down if fast < slow

Rules:

Do not trade when kalman is flat/compressed:

abs(fast−slow) < epsilon AND slopes small → “Chop”

Entries should prefer retest not raw crossover:

After regime change, wait for price to retest fast/slow and reject, then signal.

Kalman should be used as:

Trend detector

Trailing stop reference in shot plan

6) Models (Ensemble, not one model)

Build three intelligence modules:

A) Baseline ML (must)

LightGBM or XGBoost

outputs: P(up/down/chop/shock), expected_move

B) Deep learning model (must, simple but real)

Use PyTorch:

TCN (preferred) OR Transformer Encoder
Inputs: last N=128 15m steps of feature vectors
Outputs: same as above (probabilities + expected move)

C) Pattern Memory (Similarity Search) (must)

Implement “find similar historical setups”:

create embeddings of recent window features (can be PCA/autoencoder/simple projection)

store embeddings for history

retrieve top-k similar windows

compute historical forward outcomes stats:

win rate, avg move, avg drawdown, time-to-TP
Use this as an additional vote/confidence.

Final decision = weighted consensus + gatekeeper.

7) Labeling & Training Targets (avoid noise)

Default horizon: H=8 candles (2h)

Label direction with volatility-adjusted threshold:

r_fwd = (close[t+H] / close[t] - 1)

vol = ATR/close

thr = max(0.0015, 0.9*vol)

Up if r_fwd > thr, Down if r_fwd < -thr, else Chop

Also compute “trend quality” label (optional) using efficiency and drawdown, for extra gating.

8) Validation (non-negotiable)

Walk-forward validation only

Purged/embargo split due to overlapping horizons

Include fees + slippage + funding risk in evaluation

Probability calibration (isotonic or Platt) so confidence is meaningful

Stress tests: slippage ×2, spread widening

Store backtest reports and show on UI.

9) Signal Decision Engine (Gatekeeper + Shot Plan)

Decision rules:

If P(chop) > 0.55 → HOLD

If expected_move <= costs * 3 → HOLD

If liquidity bad (spread z-score high) → HOLD

If shock detected → only Shock engine allowed

If trade allowed:

LONG if P(up)>threshold and engine agrees

SHORT if P(down)>threshold and engine agrees

Shot Plan:

Entry zone: ±0.25*ATR around trigger level

Stop: structure or 1.3–2.0*ATR

TP ladder: TP1=1R, TP2=2R, trail using Kalman fast

Time stop: exit plan if no follow-through in 3 candles

Expected hold time estimated from historical similar patterns + regime

Output must be JSON saved to signals.
