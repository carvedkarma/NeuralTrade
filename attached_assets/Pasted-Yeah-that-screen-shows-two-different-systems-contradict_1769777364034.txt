1) Your UI is mixing two “worlds”: price vs return

Top row says:

Predicted Range: $22,708 – $23,176

Expected (Median): $22,946

Upside(90%): +72.00%

Downside(10%): -72.57%

But inside the forecast card you show:

Current: $82,772

q10: $81,624

q90: $83,307

Return distribution: -1.39% / -0.83% / -0.35% / +0.12% / +0.65%

These are not compatible.
If q10/q90 are ~±1–2%, you cannot also have ±72% upside/downside.

✅ Conclusion: The top row is using a different base price (23k) and/or converting returns to prices incorrectly.

Fix

Pick one canonical interpretation and use it everywhere:

Option A (recommended): quantiles are returns

q10, q50, q90 are returns (e.g. 0.0065 = +0.65%)

Price quantiles should be:

p10 = currentPrice * (1 + q10)

p50 = currentPrice * (1 + q50)

p90 = currentPrice * (1 + q90)

Upside(90%) should be:

upsidePct = q90 * 100

Downside(10%) should be:

downsidePct = q10 * 100

Option B: quantiles are price deltas

p10 = currentPrice + q10
… (less likely in your setup)

Right now you’re clearly mixing these in different widgets.

2) Your “current price” is inconsistent (82k vs 23k)

In one place you show:

In another:

Predicted Range around $23,000

That means one of these is happening:

You are reading different symbols (BTC vs something else)

Or you’re using a stale/old cached price from earlier BTC cycle

Or you’re applying a scaler inverse-transform incorrectly and interpreting scaled values as price

4) Upside/Downside percent is almost certainly computed with the wrong denominator

If you compute:

upside = (p90 - p10) / p10 or something like that
you can get huge percentages even with small moves if p10 is wrong / scaled.

But your return distribution says q90 is only +0.65%. That’s the correct upside.

downsidePct = q10*100

If quantiles are prices:

downsidePct = (p10/current - 1)*100

Do not mix.
