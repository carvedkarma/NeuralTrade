Here’s an exact, end-to-end training pipeline designed for your dataset (multi-asset BTC/ETH/SOL/BNB, multi-timeframe 1m/5m/15m/1h/4h OHLCV). It’s built to avoid the usual traps: leakage, misaligned timestamps, and mixing timeframes incorrectly.

0) Goal + Output

Train models that output tradeable signals without leakage.

Primary target (recommended):

For each symbol at time t (on a base timeframe, e.g. 1m), predict:

future return over horizon H (e.g. 15m / 60m)

optionally direction (up/down) + uncertainty

Then convert predictions into: enter / exit / no-trade.

1) Data Standardization (DB → Parquet)
1.1 Canonical schema

For each timeframe table:

ts (UTC, ms) -> convert to UTC datetime

symbol

open, high, low, close, volume

1.2 Sort + de-dup + integrity checks

For each (symbol, timeframe):

sort by ts

drop duplicates on ts (keep last)

enforce high>=max(open,close), low<=min(open,close)

enforce constant cadence:

1m: 60s; 5m: 300s; 15m: 900s; 1h: 3600s; 4h: 14400s

mark gaps (don’t forward-fill prices blindly)

1.3 Store

Write as partitioned Parquet:
data_parquet/timeframe=1m/symbol=BTCUSDT/*.parquet

This speeds training massively.

2) Time Alignment Strategy (Multi-timeframe done correctly)

Pick a base timeframe for training samples (start with 1m, later you can do 15m).

For each base timestamp t on 1m:

attach “context features” from higher TFs (5m/15m/1h/4h) using as-of join:

for each TF, use the most recent candle close timestamp ≤ t

NEVER use candles that end after t (leakage)

This produces one row per 1m candle with multi-timeframe context.

3) Feature Engineering (Leak-proof)

Do features per (symbol, timeframe) then merge.

3.1 Core transforms (per TF)

Compute on close and OHLCV:

log returns: r1 = log(close/close[-1])

rolling volatility: std(r) over [20, 60, 240] windows (scaled for TF)

EMA ratios: close/ema(close, 20) - 1

RSI(14), MACD (12/26/9)

ATR(14) normalized: ATR/close

candle shape:

body = (close-open)/open

wick_up = (high-max(open,close))/open

wick_dn = (min(open,close)-low)/open

volume:

log1p(volume)

volume z-score rolling

regime:

trend strength: slope of EMA20 over window

volatility regime bucket (low/med/high)

3.2 Cross-asset features (optional but powerful)

At time t for BTC base row:

include returns/volatility of ETH/SOL/BNB at same t (aligned by base TF)

include correlation features (rolling corr BTC-ETH etc.)

This helps generalization.

4) Labels (Targets)

You should train on returns not raw prices.

4.1 Define horizons

Choose 2–3 horizons:

H1 = 15m

H2 = 60m

H3 = 240m (optional)

4.2 Label definition

For base timeframe sample at t (1m):

future log return:

y_H = log(close[t+H]/close[t])

optional classification:

class = 1 if y_H > +thr

class = -1 if y_H < -thr

else 0 (no-trade)

Pick thr based on fees/slippage (e.g. 0.0008–0.0015).

4.3 Leakage checks

your features must only use data ≤ t

your label uses strictly > t

5) Dataset Building (Sequences)

Models like Transformer/LSTM want sequences.

5.1 Window length

Base TF = 1m:

seq_len = 256 (about 4h of history) or 512 if GPU allows
Include all merged features for each time step.

5.2 Sample format

Each training sample:

X: shape [seq_len, num_features]

y: horizon returns (multi-head output) shape [num_horizons]

5.3 Sampling strategy

Markets are mostly “no move”. Avoid imbalance:

stratify samples by absolute future return buckets

or oversample rare big moves

but keep time order within train splits

6) Train/Val/Test Splits (Time-series safe)

Do walk-forward (best) or simple chronological split.

Recommended for 3y data:

Train: first 70%

Val: next 15%

Test: last 15%

Even better (walk-forward):

Train 12 months → Val 2 months → Test 2 months

roll forward and average performance

Never random split.

7) Normalization (Critical)

Do scaling per symbol + per timeframe but fit scaler on train only.

Best approach:

For each feature:

robust scaling (median/IQR) or z-score

For returns/ratios already near 0, scaling is mild

Save scalers to disk for inference.

8) Model Architecture Options (Use 1 first)

Start with one stable model:

Option A: Temporal Fusion Transformer (TFT) (best for multivariate time series)

Inputs: known past features (everything), optional static embedding per symbol

Outputs: multi-horizon returns + quantiles

Option B: Transformer Encoder (simpler)

pos enc + 6 layers, d_model 256–512

global pooling on last token

multi-head regression outputs (H1/H2/H3)

Option C: BiLSTM + attention (fast, strong baseline)

My recommendation:
Start with Transformer Encoder for speed + simplicity, then move to TFT.

9) Training Objective (What to optimize)

Avoid plain MSE only.

9.1 Regression loss (stable)

Huber loss on y_H

multi-horizon weighted: weight shorter horizons more initially

9.2 Directional component (helps trading)

Add:

sign_loss = BCEWithLogits(sign(y)) or focal loss on up/down

9.3 Optional quantiles (risk-aware)

Predict q10/q50/q90 with pinball loss → use uncertainty for position sizing.

10) Metrics (Trading-relevant)

During validation/test compute:

MSE / MAE on returns

directional accuracy (up/down)

correlation(pred, actual)

hit rate above threshold

simulated PnL with:

fees + slippage

max positions / cooldown

only trade when |pred| > threshold

If PnL isn’t improving, your model is not useful.

11) Training Loop Setup (RTX 4070 friendly)

mixed precision (fp16/bf16)

gradient clipping (1.0)

cosine LR schedule + warmup

early stopping on val PnL or val corr

Typical settings:

batch size: 64–256 (depends on seq_len/features)

lr: 1e-4 to 3e-4

epochs: 10–50

weight decay: 1e-2

12) Deployment Pipeline (Inference)

At inference time (live):

Pull latest 1m candle(s)

Update feature buffers per TF

As-of join higher TF features

Apply saved scalers

Build last seq_len window

Model predicts returns + uncertainty

Decision layer:

trade only if predicted return > threshold AND uncertainty acceptable

optional: confirm with higher TF trend (1h regime)
