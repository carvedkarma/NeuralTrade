1) Fix the “14,020 candles = 1 year?” mismatch

On 15m timeframe:

~96 candles/day

1 year ≈ 35,000 candles

So 14,020 candles ≈ ~146 days (~4.8 months), not a year.

Suggestion

In the UI, show both:

candles_count

days_covered

expected_for_365d

“completion % to 1 year”

And update the backfill trigger:

show “Fetch 1 year” button if days_covered < 365, not “< 300”.

2) Add gap detection + integrity checks (this prevents silent corruption)

Backfills often “look complete” but have missing time ranges.

Add a background integrity report endpoint:
GET /api/historical/integrity

Return:

missing candle ranges (ts start/end)

duplicate counts

last candle ts

% completeness per day/week

resample sanity checks (15m boundaries aligned)

Display a small “Data Health” badge in the Learning panel:

✅ Complete

⚠️ Missing ranges

❌ Out of sync (features not updated)

3) Make backfill resumable and idempotent (bulletproof)

You already have progress tracking — great. Make sure it supports:

resume after restart

continue after API rate-limit

no duplicates

Suggestion

store backfill_job in DB:

status, current cursor, start/end ts, updated_ts

UI can reattach to a running job.

4) Ensure training uses all historical data (not just “recent window”)

You previously had the “Training Data Range: last few days” confusion.

Suggestion

add these two fields:

training_range_used (start/end)

full_history_range_available (start/end)

Show both in UI so you can see if it’s accidentally training only on the latest slice.

5) Upgrade metrics: stop using “accuracy” and “win rate” alone

Now that leakage is fixed, this is the next common trap.

Add these to Performance:

Profit Factor

Expectancy per trade (after fees)

Max drawdown + duration

Trade count per regime

Win rate ex-HOLD + HOLD rate separately

Calibration plot (win rate vs confidence buckets)

This makes the system “trustable”.

6) Paper trading: enforce risk rules so results mean something

Earlier you had exposure > 200%. That ruins evaluation.

Hard limits:

risk per trade default: 0.25%–0.5%

max exposure: 100% (or less)

one open position at a time (until stable)

ATR-based stops; prevent stops tighter than fees+slippage

Add an “execution audit log” panel:
For every attempted trade, show:

allowed/blocked + reason

computed edge vs cost

confidence components
This kills hidden bugs fast.

7) Improve feature importance display (avoid “always same”)

Now that your architecture is clean, make explainability real:

show feature importance by regime

show importance for last 30 days vs full history

store with model_version

If it stays static after retrains, you’ll know learning isn’t updating.

8) Add “Versioning” everywhere (prevents phantom changes)

Add model_version, pattern_version, feature_set_version to:

API responses

UI headers

paper trades

So when performance changes, you can tell what changed.
