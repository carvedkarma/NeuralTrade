GOAL:
Pivot from 3-class direction (SHORT/HOLD/LONG) to a professional “ENTRY QUALITY” model using the existing 57-feature pipeline (STF47 + HTF10). Direction is NOT predicted; it is derived from HTF trend. The model predicts whether a trend-following trade setup is worth taking (ENTER=1) or not (ENTER=0). Keep the current infrastructure (data loading, feature building, training loop, walk-forward eval), but change labeling + model heads + inference logic accordingly.

CONSTRAINTS:
- Do NOT add new data sources.
- Reuse compute_all_features() (57 features) and feature versioning.
- Prevent leakage: labels must use only future data beyond t; features only use <= t. HTF already shifts by 1 bar (keep it).
- Keep SL/TP/expiry consistent between labeling and evaluation.
- Version bump to: v3.1.0_enter_quality_stf47_htf10 (or similar).
- Inference MUST hard-fail on feature_version mismatch (not warn).

================================================================================
1) LABELING: Build ENTER labels using HTF-gated Triple Barrier
================================================================================

Implement a new labeling function (e.g., label_enter_quality(df_15m, htf_cols, params)):

A) Compute HTF trend direction (already in features, but if needed recompute from HTF indicators):
- Use the existing HTF features:
  - h1_trend_sign (or sign(h1_sma20_slope))
  - h4_trend_sign (or sign(h4_sma20_slope))
- Define “trend aligned”:
  trend_align = (h1_trend_sign == h4_trend_sign) and (h1_trend_sign != 0)

B) Candidate gate (only these bars are allowed to become ENTER=1):
- trend_align == True
- abs(h1_sma20_slope) > slope_eps  (start with slope_eps = 0.05 if slope is ATR-normalized, otherwise pick a small number and log distribution)
- Optional: only allow when h1_range_pos is not strongly against the trend:
  - if trend is LONG: h1_range_pos > 0.2
  - if trend is SHORT: h1_range_pos < 0.8

For non-candidates:
- ENTER = 0
- side_hint = 0 (optional)

C) Triple Barrier evaluation (candidates only):
For each candidate bar at index i:
- side = LONG if h1_trend_sign > 0 else SHORT
- entry_price = close[i]
- Compute ATR for sizing barriers (use existing 15m ATR feature if available, else compute ATR14 on 15m):
  atr = atr15m[i]
- Set barriers:
  SL = entry_price - side* (k_sl * atr)    (side=+1 for long, -1 for short)
  TP = entry_price + side* (k_tp * atr)
  expiry = i + horizon_bars  (start horizon_bars=24 or 32)
- Walk forward until expiry:
  - if side LONG: TP hit if high[j] >= TP, SL hit if low[j] <= SL
  - if side SHORT: TP hit if low[j] <= TP, SL hit if high[j] >= SL
- Label:
  - If TP hit first => ENTER=1
  - Else (SL first or expiry) => ENTER=0

Save additional debug columns:
- enter_label (0/1)
- side_hint (+1/-1/0)
- tp_price, sl_price, expiry_index
- outcome: "TP"/"SL"/"EXP"/"NO_CANDIDATE"

IMPORTANT: Keep this consistent with trading evaluation later.

================================================================================
2) MODEL: Replace direction head with ENTER head (+ optional side head)
================================================================================

A) Minimal model change:
- Remove/disable the 3-class direction head loss.
- Add a binary classifier head: enter_head -> logits shape [B,1]
- Loss: BCEWithLogitsLoss (use pos_weight if class imbalance is high)
- Keep other heads (vol_state etc.) optional; focus on enter_head first.

B) (Optional, phase 2) Add a side head:
- side_head predicts LONG vs SHORT (2-class) only for candidate bars (or for ENTER=1 bars).
- But for now, direction can simply come from HTF trend sign; keep side_head disabled unless requested.

================================================================================
3) TRAINING LOOP CHANGES
================================================================================

- Dataset targets now include enter_label (0/1) and side_hint (optional).
- Compute enter_loss each batch:
  enter_loss = BCEWithLogitsLoss(logits, enter_label)
- Total loss = enter_loss (+ any existing auxiliary losses you decide to keep, but keep it simple initially)
- Log:
  - enter positive rate in train/val
  - enter precision/recall/F1 at a threshold (0.5)
  - PR-AUC if easy to compute (better than accuracy for imbalance)

Early stopping should monitor val enter loss (or PR-AUC).

================================================================================
4) INFERENCE + TRADING POLICY (NO MORE DIRECTIONAL CONFIDENCE SWEEPS)
================================================================================

Inference output should include:
- p_enter = sigmoid(enter_logit)
- side = sign(h1_trend_sign) (HTF direction)
- entry/sl/tp computed using same k_sl/k_tp/atr logic as labeling
- Only trade if:
  - p_enter >= enter_threshold (start 0.55 and sweep 0.50..0.70)
  - AND trend_align True
  - AND abs(h1_sma20_slope) > slope_eps

Action:
- if p_enter passes -> LONG/SHORT (from HTF)
- else HOLD

Remove the old “confidence = softmax prob of direction” gating from production path.
